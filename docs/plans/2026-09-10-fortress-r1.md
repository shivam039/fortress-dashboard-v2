# FORTRESS-R1 implementation plan

Goal: reproducible historical score observations and forward labels without
changing scoring semantics or manufacturing historical information.

Architecture: offline, standard-library JSONL-to-SQLite pipeline. An immutable
input bundle declares sessions, historical membership, score runs with input
availability evidence, original scored rows, and unadjusted closing prices.
Explicit exchange sessions define horizons; missing observations stay missing.
Input hashes and methodology accompany the normalized output.

Relevant existing code: stock_scanner/logic.py apply_advanced_scoring performs
cross-sectional normalization and uses current metadata upstream. utils/db.py
save_scan_results stores raw scored rows but does not archive input publication
timestamps or scoring revisions. Historical reconstruction from that alone is
not defensible. No live modules will change. No legacy-data certification,
provider acquisition, weight tuning, UI, performance claims, or rescoring.

1. Add tests/backend/test_historical_dataset.py first. Verify collection fails
   because engine.research.historical_dataset does not exist.
2. Implement engine/research/historical_dataset.py and package marker. Validate
   input schema, timestamps, provenance, uniqueness, and references. Select only
   same-session snapshots available by session cutoff. Preserve Score exactly.
3. Generate normalized observations and labels using calendar positions, with
   nulls and reason codes. Include hashes and deterministic ordering. Never
   overwrite an existing output or leave a partial database after failure.
4. Document every field, score mapping, return convention, eligibility rule,
   known data limitations, and regeneration/verification commands in
   docs/research/historical_dataset.md.
5. Run focused pytest and existing scorer regression tests, ruff, and diff
   checks. Commit only these files, push the story branch, create a PR.
