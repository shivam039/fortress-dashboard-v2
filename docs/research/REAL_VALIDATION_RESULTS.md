# FORTRESS-V1: Real-Market Validation Results

**Status: no valid R1 dataset could be built in this environment. R2/R3/R4 were not run
against fabricated or uncertified data, per this story's explicit constraints.**

This story's goal was to turn the existing R1→R2→R3→R4 research framework into
populated, reproducible real-market evidence. The framework (`engine/research/*`,
documented in `docs/research/historical_dataset.md`,
`docs/research/score_forward_return_validation.md`,
`docs/research/feature_correlation_ablation.md`,
`docs/research/walk_forward_validation.md`) is real, tested, and unchanged by this
story. What is missing is a real, point-in-time-provenanced input bundle to feed it.
This document reports that gap honestly instead of manufacturing a dataset to fill it.

## Step 1 — Inventory of usable historical sources

| Source | What it actually contains | Provenance class | Usable for R1? |
| --- | --- | --- | --- |

**Conclusion of Step 1:** there is no A- or B-provenance real market-observation
source available to build an R1 bundle in this repository or in this execution
environment. Every candidate either (a) is explicitly ruled unsafe by the R1
methodology document itself, (b) is synthetic test fixture data mislabeled only by
its filename similarity to the real production database, or (c) requires outbound
network access this sandboxed session does not have.

## Steps 2–5 — R1 build, R2, R3, R4

**Not executed against real data**, because Step 1 found no eligible input. Building
an R1 bundle from the `fortress_history.db` test fixtures, or from today's live
metadata backdated to look historical, would violate this story's explicit
constraints ("Do NOT fabricate historical metadata," "Do NOT backdate current
fundamentals/news," "If historical data is insufficient for a statistically useful
result, report that honestly"). No R1 SQLite dataset, R2 validation report, R3
ablation report, or R4 walk-forward report was produced, because none of them would
be evidence of anything — they would be a demonstration of the pipeline running on
data it should not be run on for research purposes.

**What was verified instead:** that the pipeline itself is intact and functions
correctly, using its own existing synthetic regression fixtures (not represented as
market evidence anywhere in this repo):

```
$ rm -f fortress_history.db
$ PYTHONPATH=.:engine .venv/bin/pytest \
    tests/backend/test_historical_dataset.py \
    tests/backend/test_forward_return_validation.py \
    tests/backend/test_walk_forward_validation.py \
    tests/backend/test_feature_correlation_ablation.py -q
39 passed in 2.10s
```

This confirms the R1 builder, R2 validator, R3 ablation analyzer, and R4
walk-forward evaluator are all present, importable, and behave as documented on
controlled synthetic input — i.e., the machinery this story was asked to populate
is ready the moment a real, provenance-qualified input bundle exists. It is not
evidence of anything about real Fortress performance.

## Required answers

1. **Does higher Fortress Score correlate with higher forward returns?** Cannot be
   determined. No real observation exists in this environment to test the
   hypothesis against.
2. **Is the relationship monotonic?** Cannot be determined, for the same reason.
3. **Does it survive untouched out-of-sample windows?** Cannot be determined — R4
   was not run against real data.
4. **Does top-N Fortress selection beat simple momentum?** Cannot be determined.
5. **Does it beat Nifty?** Cannot be determined.
6. **In which regimes does it work/fail?** Cannot be determined.
7. **What is the sample size?** **Zero** real, point-in-time-provenanced
   observations.
8. **What are the largest limitations?**
   - No historical archive of Fortress scan output was ever captured with the
     provenance metadata the R1 contract requires (input hashes, availability
     timestamps, scoring revision, full normalization universe per run). Every
     legacy scan row is explicitly disqualified by the R1 spec itself.
   - This execution environment has no outbound network access to any of
     Fortress's market-data providers (NSE Bhav Copy, INDstocks, yfinance),
     verified by direct connection tests, so a new real bundle cannot be
     assembled from here either.
   - The only populated local database is synthetic pytest/dev fixture data
     (flat prices, uniform scores, present-day timestamps) that must not be
     mistaken for, or substituted as, real market history.
9. **Is the evidence sufficient for:**
   - **Research only** — No. There is no evidence yet, only infrastructure.
   - **Paper trading** — No change from what T1/T2/U2 already established:
     paper trading is not gated on this story's evidence, but nothing here adds
     support for it either.
   - **Small-live experimentation** — No.
   - **Normal live trading** — No.

## What would actually close this gap

1. **Acquire real historical data with provenance**, either by:
   - Running Fortress scans going forward from a network-enabled environment,
     archiving each run into an immutable bundle that satisfies every field in
     `docs/research/historical_dataset.md` (`manifest.json`, `sessions.jsonl`,
     `membership.jsonl`, `runs.jsonl`, `snapshots.jsonl`, `prices.jsonl`,
     content-hashed `inputs/`), and building up real sample size over calendar
     time; or
   - Sourcing an already-existing, independently vintaged historical archive
     (e.g., a paid point-in-time NSE dataset) with genuine publication
     timestamps that can be adapted into the same bundle format — the R1
     builder does not care where the bundle came from, only that its
     provenance claims are true.
2. Only once such a bundle exists should `engine.research.historical_dataset`,
   `research.forward_return_validation`, `research.feature_correlation_ablation`,
   and `research.walk_forward_validation` be run for research purposes, using the
   exact commands documented in each module's `docs/research/*.md` file.
3. This story's honest conclusion should not be read as "the framework is
   unfinished" — R1 through R4 are implemented and tested. It should be read as
   "Fortress has not yet operated long enough, or acquired a properly vintaged
   external archive, to have real evidence about itself."
